# BLOCK WORLD: อาณาจักรนักสร้างโลกแห่งคำ

เกมเว็บต้นแบบนวัตกรรมการเรียนรู้ภาษาไทยสำหรับนักเรียน ป.3 แบบ Cooperative Adventure Quest + Sentence Tile Building + City Building ผู้เล่น 2–4 คนเล่นเป็นทีมบนเครื่องเดียว (ผลัดกันเล่น) ช่วยกันแต่งประโยค ผ่านบอส 3 โซน สะสมคริสตัล 3 ดวง และปลดผนึกหอคอยกลาง

## เปิดเล่นทันที

ดับเบิลคลิกไฟล์ **`blockworld.html`** (ไฟล์เดียว รวมโค้ดและฟอนต์ไทยไว้แล้ว เล่นแบบออฟไลน์ได้ ไม่ต้องติดตั้งอะไร) รองรับเบราว์เซอร์ Chrome, Edge, Safari และ Firefox รุ่นปัจจุบัน ทั้งบนคอมพิวเตอร์และแท็บเล็ต

PIN โหมดครูตั้งต้นคือ **1234** เปลี่ยนได้ตอนเริ่มเกมหรือในแดชบอร์ดครู

## พัฒนาต่อ

```bash
cd blockworld
npm install
npm run dev        # เปิดเซิร์ฟเวอร์พัฒนา
npm test           # ทดสอบกติกาและข้อมูล (vitest)
npm run build      # ตรวจชนิดข้อมูล + สร้าง dist/ และ blockworld.html ใหม่
npm run smoke      # เล่นเกมจริงในเบราว์เซอร์ตั้งแต่ต้นจนจบ (ต้องมี Playwright + Chromium)
```

## วงจรการเล่น

1. หน้าเริ่มเกม: เลือกผู้เล่น 2–4 คน กรอกชื่อ (ค่าตั้งต้นเป็นชื่อสมมติ) เลือกตัวละคร และวิธีรับรองผลงาน
2. ถึงตาใคร กด **ทอยลูกเต๋า** (หน้า 1,1,2,2,3,3) ตัวเดินเดินทีละช่องในโซนที่ปลดล็อก แล้วเปิดผลของช่อง: เรียนรู้ ภารกิจ คำ โบนัส สร้างสรรค์ สร้าง พัก หรือประตูบอส
3. ภารกิจมี 4 ขั้น: **สถานการณ์ปัญหา** (เกิดปัญหาอะไร? / เราจะแก้ได้อย่างไร?) → **สร้างคำตอบ** ด้วยบล็อกคำหรือพิมพ์เอง พร้อมเหตุผล → **แลกเปลี่ยนเรียนรู้** (เพื่อนทุกคนเสนอความคิดอย่างน้อยคนละ 1 ครั้ง) → **ตรวจและรับรอง** โดยครู/โค้ช
4. ผ่านภารกิจได้บล็อกก่อสร้าง 1 ก้อน ใช้สร้างเมืองได้ กด **จบตา** ส่งให้คนถัดไป
5. **กระดานภารกิจ** แสดง 5 หัวข้อของโซนเสมอ เลือกทำได้โดยไม่ต้องรอทอยให้ตกช่อง (ตาละ 1 ภารกิจใหม่ ภารกิจค้างทำต่อได้เสมอ) ความสุ่มจึงไม่ปิดโอกาสเรียน
6. ครบ 5 หัวข้อที่ผ่านการรับรอง บอสเปิด: ทำภารกิจย่อย 3 ข้อ (พลังบอสลดทีละขั้น) ทีมทบทวนร่วมกัน ครูรับรอง ได้คริสตัล และปลดล็อกโซนถัดไป
7. ครบ 3 คริสตัล หอคอยเปิด ทำด่าน F (จับเวลา 2 นาทีสำหรับฝึก), FL (อย่างน้อย 3 แนวทาง), O (ร่ม / หุ่นยนต์ / เมล็ดพันธุ์ เปลี่ยนชุดได้), E (ขยาย “นกบิน”) ครบแล้วเข้าสู่ฉากจบพร้อมสรุปผลงานรายคน

คีย์ลัด: `R` ทอยลูกเต๋า · `E` จบตา · `M` กระดานภารกิจ · `H` ฐานการช่วยเหลือ · `Esc` ปิดหน้าต่าง

## หลักการสำคัญที่ออกแบบไว้

- **ไม่ตัดสินประโยคด้วยการเทียบสตริง**: ระบบตรวจเบื้องต้นดูแค่กลุ่มคำ (เช่น มีคำบอกเวลา/สถานที่ไหม มีคำลงท้ายสุภาพไหม) และแสดงเป็นคำแนะนำ การให้ผ่านต้องผ่านครู/โค้ช (PIN) หรือโหมดเพื่อนทุกคนเห็นพ้อง (ครูตรวจย้อนหลัง)
- **คำใบ้และตัวอย่างคำตอบเป็นของครูเท่านั้น** แสดงเมื่อเข้าโหมดครู เด็กขอตัวอย่างใกล้เคียงได้จากศูนย์การเรียนรู้และฐานช่วยเหลือ
- **ขอความช่วยเหลือไม่หักคะแนน** ระบบบันทึกเพียงว่าใช้ความช่วยเหลือแบบใด
- **แยกกิจกรรมฝึกจากเครื่องมือวิจัย**: แดชบอร์ดแสดงข้อความ “ข้อมูลกิจกรรมฝึก ไม่ใช่คะแนนเครื่องมือวิจัยที่ผ่านการตรวจสอบ” ไม่มีข้อสอบจริงหรือเฉลยในเกม ตัวบ่งชี้ 1.1–4.3 เป็นช่องบันทึกพฤติกรรม ยังไม่เท่ากับการให้คะแนนตาม rubric จริง
- **ฉากจบไม่ตีตราใคร**: สรุปผลงานรายคนเน้นจุดเด่นและการมีส่วนร่วม
- **ข้อมูลอยู่ในเครื่องเท่านั้น** (localStorage) ไม่มี backend หรือ API key ส่งออกได้เป็น JSON และ CSV (มี UTF-8 BOM ให้ Excel อ่านภาษาไทยถูก)

## สิ่งที่ควรรู้ / ยังไม่ได้ทำ

- **ไม่ได้รับไฟล์ `เนื้อหา(1).docx` และ `BOARD_REFERENCE.png`**: ชื่อ 15 หัวข้อและโจทย์ P01–P15 จึงยึดตามรายการในสเปก ส่วนแผนที่ใช้แบบ SVG ที่สร้างเองตามคำบรรยายภาพอ้างอิง (เกาะลอย น้ำตก สะพานไม้ ช่องสีฟ้า เขียว เหลือง แดง) หากได้ภาพจริง ใส่เป็นพื้นหลังของ `Board.tsx` แล้ววาง hotspot ตามตำแหน่ง `tilePos()` ได้
- **AR เป็นตัวอย่างจำลอง** (ป้าย “ตัวอย่างการแสดงผล AR”) ไม่ได้สแกน AR จริง โมดูล `src/ar/arScenes.ts` แยกไว้ให้เชื่อม WebXR หรือ marker ภายหลัง
- เสียงอ่านใช้ SpeechSynthesis ของเบราว์เซอร์ คุณภาพเสียงไทยขึ้นกับเครื่อง ถ้าไม่รองรับจะขึ้นข้อความแจ้งให้อ่านบนจอแทน
- การลาก-วางบล็อกคำใช้ได้บนคอมพิวเตอร์ บนแท็บเล็ตใช้การแตะและปุ่ม ◀ ▶ ✕ แทน
- PIN ใช้แยกโหมดครูกับผู้เล่นแบบง่าย ไม่ใช่ระบบรักษาความปลอดภัย
- เรื่องราว บอส รางวัล และตัวอย่างคำถามเป็นข้อเสนอการออกแบบ ควรให้ครูผู้เชี่ยวชาญตรวจทานภาษาก่อนใช้จริง
